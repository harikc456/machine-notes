# KV Cache Transform Coding for Compact Storage in LLM Inference

**Authors**: Konrad Staniszewski, Adrian Łańcucki
**Affiliation**: NVIDIA, University of Warsaw
**Venue**: ICLR 2026, arXiv:2511.01815

## Core Idea

`kvtc` (Key-Value Transform Coder) applies classical transform-coding theory (as in JPEG/image codecs) to compress KV caches for both on-GPU and off-GPU storage. Three-stage pipeline:

1. **Feature decorrelation** (PCA): Compute orthonormal basis V from SVD of calibration data. Project KV vectors to decorrelated principal components.
2. **Adaptive quantization**: Dynamic programming allocates bits per principal component proportional to variance (high-variance components get more bits). Quantization done with channel-wise scalar quantizers.
3. **Entropy coding**: DEFLATE (nvCOMP) on quantized coefficients — exploits residual statistical structure.

One-time calibration per (model, compression ratio) pair — takes ~10 min on H100 for 12B model. Model parameters unchanged. Operates in between decode steps or during prefill→decode transition.

## Key Design Decisions

**Cross-head alignment**: Key heads from different attention layers share a common latent subspace (up to orthogonal rotation). kvtc aligns caches across heads before PCA, reducing per-head calibration cost.

**Sliding window + attention sinks excluded**: Recent W=128 tokens and oldest s=4 (attention sinks) are NOT compressed — these are critical for attention accuracy at high compression ratios.

**Calibration generalization**: PCA basis trained on one domain transfers to another with <5% relative error increase. One basis per model suffices for diverse workloads.

## Results

- **20× compression** (kvtc_20×) at maintained reasoning and long-context accuracy
- **40× compression** (kvtc_40×) at modest accuracy drop
- Peak compression ratios reported: kvtc_8×: 9–10× actual, kvtc_16×: 18–22×, kvtc_32×: 34–44×, kvtc_64×: 64–88× (DEFLATE contributes variable portion)
- Benchmarks: GSM8K, LiveCodeBench, MATH-500, MMLU, LongBench, Qasper, RULER
- Models tested: Llama 3 (3.1 8B, 3.3 70B Instruct), Mistral NeMo 12B, R1-Qwen 2.5
- Consistently outperforms token eviction, inline quantization, and SVD-based baselines

## Serving Motivation

KV caches in multi-turn chat are reusable across conversation turns via prefix sharing. Compressed storage extends cache lifetime on GPU HBM/DRAM by compression ratio factor — a 20× lifetime extension can keep frequently used caches hot across many users on a decode node.

KV transfer bandwidth (prefill→decode nodes) also scales proportionally with compression.

## vs. Alternative Approaches

| Method | Approach | Limitation |
|---|---|---|
| Token eviction (H₂O, TOVA) | Discard tokens | Irreversible; struggles with retrieval |
| Inline quantization (INT8/INT4) | Fixed bit-width, per-block norm | Doesn't exploit low-rank structure |
| SVD per prompt (xKV, SVDq) | Per-prompt decomposition | Expensive O(n²) per prompt; not generalizable |
| **kvtc** | PCA + DP bit allocation + entropy coding | One-time calibration; fully generalizable |
